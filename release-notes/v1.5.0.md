# v1.5.0

## Highlights

- Added a shared deterministic planner for execution, dry-run, and explain.
- Added execution metrics to JSON reports and run history.
- Added read-only duplicate detection with `filemindr duplicates <directory>`.

## Features

- Destination reservations keep numbered conflict names consistent in explain,
  dry-run, and execution.
- Execution revalidates source and destination state before publishing an
  operation; file/directory destination collisions are reported as errors.
- Reports and history include duration, throughput, operation counts, rule
  matches, skips, errors, and planned/completed totals.
- Duplicate scans group files by size, hash candidates in bounded chunks, skip
  symlinks, honor optional profile ignore patterns, and report files that could
  not be verified. The command does not modify files.

## Compatibility and safety

- Existing CLI commands and YAML configuration fields remain supported.
- Existing report summary and event fields remain; reports and finalized history
  metadata gain a `metrics` object.
- Physical cross-volume moves and external/network filesystem semantics still
  require additional integration validation.

## Validation

- 155 tests passed and 3 symlink-related tests skipped on each local Python
  version tested (3.12, 3.13, and 3.14).
- GitHub Actions passed all nine Windows, macOS, and Ubuntu matrix jobs across
  Python 3.12–3.14.
- Ruff lint, wheel and source builds, Twine metadata checks, and installed-package
  smoke checks passed.

## Distribution

Publication is handled by the manual `Publish Python Package` workflow dispatch
on `development` after its CI and artifact checks pass.
